## 업무 데이터 확인

주문 목록 API는 주문 1건을 반환했다. 구매자 ID는 이미 일부 마스킹되어 있으며, 상품은 오토바이/자전거 핸들 바 테이프다.

- 주문일: 2026-07-13 12:15:00
- 발송일: 2026-07-13 13:09:00
- 배송완료일: 2026-07-28 12:34:20
- 구매결정일: 2026-08-05 01:07:00
- 송금일: 2026-08-06 00:00:00 (계좌송금)
- 결제금액: 6,850원 / 정산금액: 6,842원 / 서비스 수수료: -26원

집계 API에는 `DT1`, `DT9`, `DT5`, `DT7` 각각에 주문 수 1, 상품금액 6,850원, 정산금액 6,842원이 표시되고 `DT6`은 0이다. 이는 동일 주문을 판매 진행 단계별로 표현한 집계로 보이며, 이 값을 단순 합산하면 주문을 중복 집계하게 된다. 또한 집계 응답의 최상위 `TotalCount`는 0인데 상태별 `OrderCount`는 존재하므로, 이 필드는 상태 합계와 다른 의미이거나 화면에서 사용하지 않는 값인지 확인이 필요하다.

배송비 및 구매결정 상세 API가 빈 결과를 반환한 것은 오류가 아니다. 두 응답 모두 `success: true`, `message: "Loaded data"`이고, 현재 필터(`sellStatusType=DT1`)에 해당하는 별도 상세 데이터가 없다는 의미다.

## 성능 관찰

- API 응답은 143.2~216.2 ms로 양호하다. API 4건의 누적 시간은 701.3 ms이며 가장 느린 요청은 주문 목록(216.2 ms)이다.
- 정적 GIF 3건은 9.3~14.0 ms이고 CDN 응답 헤더에 `x-cache-result: TCP_REFRESH_HIT`가 있어 캐시를 활용하고 있다.
- 다만 XHR 4건은 모두 같은 필터를 전송한다. 화면이 이들을 순차 대기한다면 병렬 요청 또는 필요한 탭/영역의 지연 로딩으로 초기 표시 시간을 줄일 여지가 있다. 캡처만으로 실제 직렬 실행 여부는 확정할 수 없다.
- 동적 JSON 응답에는 `Cache-Control: private, s-maxage=0`가 적용되어 사용자별 판매·정산 정보의 공유 캐시를 방지한다.

## 보안 및 운영 관찰

- 모든 요청은 HTTPS이며 `Strict-Transport-Security: max-age=63072000; includeSubDomains`가 반환되어 전송 보호는 적절하다.
- 캡처의 요청 헤더에는 `ASP.NET_SessionId`, `ESM_AUTH`, `ESM_REQUEST_AUTH_PC`, `ESM_TOKEN` 등 세션/인증 값이 평문으로 보관되어 있다. 특히 JWT 형태의 `ESM_TOKEN`은 재사용 가능한 인증 정보일 수 있으므로 캡처 파일을 비밀정보로 취급하고 공유·커밋·티켓 첨부를 금지해야 한다. 노출 가능성이 있으면 해당 세션 로그아웃 및 토큰/세션 폐기를 권장한다.
- 인증 쿠키가 `pics.esmplus.com` 이미지 요청에도 전송된다. 같은 상위 도메인 내 의도된 구성일 수 있으나, `Domain`/`Path`/`Secure`/`HttpOnly`/`SameSite` 속성을 서버 측에서 재점검해 정적 자산 서브도메인에는 불필요한 인증 쿠키가 전달되지 않도록 범위를 최소화하는 것이 좋다.
- 응답의 `X-Powered-By: ASP.NET, ARR/3.0`은 구현 기술 정보를 노출한다. 기능상 문제는 아니지만 외부 노출 서비스라면 제거를 검토할 수 있다.
- 이미지 CDN의 `Access-Control-Allow-Origin: *`는 공개 이미지에 자연스러운 설정이다. 인증이 필요한 이미지로 확대될 경우에는 유지하면 안 된다.

## 권장 조치

1. 이 네트워크 캡처를 민감정보로 취급하고 보관 기간·접근 권한을 제한한다. 인증값이 외부에 노출됐을 가능성이 있으면 세션/토큰을 무효화한다.
2. 정적 이미지 도메인으로의 인증 쿠키 전송이 필요하지 않은지 확인하고, 필요 없다면 쿠키 스코프를 축소한다.
3. 화면의 상태별 집계를 합산하는 소비 코드가 있다면 중복 주문 집계를 피하도록 `SellStatusType`의 업무 의미와 `TotalCount` 사용처를 검증한다.
4. 초기 렌더링 경로에서 네 API가 직렬이라면 병렬화 또는 지연 로딩을 측정 후 적용한다.

## 결론

이번 캡처에서 기능적 네트워크 오류는 없다. 주문 상세 1건은 정상 반환됐고, 배송비·구매결정 상세는 필터 기준으로 정상적인 빈 결과다. 우선순위는 캡처 내 인증정보 보호와 정적 서브도메인으로 전달되는 인증 쿠키 범위 점검이다.
